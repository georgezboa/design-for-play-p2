## Part 0 — 共同语法

后面每一关都引用本节,不重复解释。

### 0.1 玩家必须能不靠文字推断出的那一句规则

先设 BRAKE 隔离风缸以减缓回压,放气,然后在压力回升越过红区之前咬合门闩。

### 0.2 四个动词与精确输入处理

| 动词 | 输入 | 条件 | 效果 |
| ---- | ---- | ---- | ---- |
| WALK | 左右方向键 | 始终 | 移动主角。`speedWalk = 200` px/s 是唯一被计入预算的时间成本 |
| BRAKE | 点按 E | `abs(player.x - brake.x) < 62` 且同 lane | 切换 `brakeSet`;为 true 时风缸被隔离 |
| VENT | 长按 E | `interactHeld` 且 `abs(player.x - vent.x) < 62` 且同 lane | 阀门开启;松键或走开立即关闭 |
| DOOR/LATCH | 点按 E | `abs(player.x - latch.x) < 62` 且同 lane | 仅在 `pressure < latchThreshold` 时咬合;否则播放机械拒绝动作 |

### 0.3 共用视觉语言

- **压力表读法**:指针角度 `Linear(-64, 28, pressure / 100)`。红区是一段
  `LAMP_ALERT` 弧,覆盖 pressure 30..100。**禁止数字读数**,靠角度读。
- **黄铜气路**:一条连续管路,`BRASS_HI`,走向恒为 `BRAKE -> VENT -> LATCH`。
  alpha 跟随 `0.3 + fraction * 0.55`,所以管路发暗即低压。
- **轮廓与安装高度**(形状与高度都必须不同):
  - `BRAKE`:地面铸铁支架,低矮、方块状、螺栓固定在底板上。
  - `VENT`:墙面黄铜阀轮,中等高度、圆形、装在竖向法兰上。
  - `LATCH`:车厢出口的爪 / 棘爪,高位、钩状、固定在门框上。
  同一关内不得有两个控件同时共享轮廓与颜色。
- **低压颜色与动画**:`pressure < 30` 时压力表 `SKY_RIM` 以 1 Hz 脉动,并有一道
  微弱高光沿气路从 `VENT` 向 `LATCH` 行进,表示窗口正在关闭。
- **失败反馈词汇**:指针爬升;门闩爪抬起一掌高又落回并发出闷响;气路绷紧。
  这三种信号取代全部文字错误提示。

### 0.4 上下文提示系统

- 同一时刻**最多一条**提示可见。
- 锚点:物件原点 + `(0, -48)`。
- 触发半径 `90`。消除半径 `160`。迟滞间隔 `160 - 90 = 70`,宽于 62px 拾取半径,
  因此不可能在边界上闪烁。
- 两个物件同时在范围内时:取最近者;距离相同时取 x 较小者。
- 淡入 `0.15s`,淡出 `0.10s`。
- 玩家离开消除半径,**或**允许该提示的条件不再成立时,提示消失。

### 0.5 规范提示字符串

- `[E] SET BRAKE`
- `[HOLD E] RELEASE AIR`
- `[E] TEST LATCH`
- `THE LINE IS RE-PRESSURIZING`

## Part 1 — Section III(x 1600..2390,守卫线 2378)

### III.1 入场状态

- `player.x = 1610`
- `pressure = 100`
- `brakeSet = false`
- `latchEngaged = false`
- 画面上:从左到右 `BRAKE`(1690)→ `VENT`(2110)→ `GAUGE`(2220)→
  `LATCH`(2330)。段落铭牌是唯一的 HUD 元素。

### III.2 从左到右的视线与因果

| 机械 | 世界 x | 在因果链中的角色 |
| ---- | ------ | ---------------- |
| BRAKE | 1690 | 第一环;隔离风缸,使窗口长到够用 |
| VENT | 2110 | 第二环;仅在长按期间开启 |
| GAUGE | 2220 | 反馈;玩家读出 brake 与 vent 的后果 |
| LATCH | 2330 | 最后一环;只在低压窗口内生效的回报 |

玩家**可以**跳过 `BRAKE` 直奔 `VENT`——这正是教学的关键。跳过时压力掉得快、回得也快,
`LATCH` 会拒绝。设了 `BRAKE` 再试,指针回爬明显变慢,管路保持松垂更久,爪咬住。
**未刹窗口 1.00s 短于 VENT→LATCH 的 1.10s 步行时间,所以只靠走路的玩家在物理上
被迫发现 BRAKE。**

### III.3 每个机械的精确功能

- **BRAKE(x 1690,y 430,地面铸铁支架)**:62px 内点按 E 切换 `brakeSet`。
  设定后手柄压下并锁住;bleed 变为 21/s,recharge 变为 9/s。
- **VENT(x 2110,y 430,墙面黄铜阀轮)**:同 lane 62px 内长按 E 开启。开启期间
  `pressure -= (brakeSet ? 21 : 30) * dt`,下限 0。长按时阀轮转动。
- **GAUGE(x 2220,y 420,齐眼高)**:**纯显示,永不作为 interactable**,因此不占用
  提示名额。指针角度对应压力,红弧 30..100。
- **LATCH(x 2330,y 430,车厢出口爪)**:62px 内点按 E。`pressure < 30` 时爪抬起
  并保持;否则抬起一掌高后落回,闷响。

### III.4 本关唯一新增变量

`recoveryTime`,完全由是否设了 `BRAKE` 决定。它是停止放气后压力停留在门闩阈值
以下的时长。

### III.5 状态转换表

| 当前状态 | 条件 / 动作 | 下一状态 | 世界反馈 |
| -------- | ----------- | -------- | -------- |
| brake=false, latch=false, pressure=100 | BRAKE 处按 E | brake=true | 手柄压下锁住 |
| pressure=100 | VENT 处长按 E | venting=true | 阀轮转动,指针以 70/s 下落(与刹车无关) |
| venting=true, brake=true | 松键 / 走开 | recovering=true (8/s) | 高光开始沿 VENT→LATCH 行进 |
| venting=true, brake=false | 松键 / 走开 | recovering=true (40/s) | 高光行进明显更快 |
| venting=true, 长按 < 400ms | 松键 | venting=false, 压力复原 | 阀轮回弹,无嘶声:阀门未坐实,气没放出去 |
| recovering=true, pressure<30, 在 LATCH | LATCH 处按 E | latch=true | 爪抬起并咬住,过关 |
| recovering=true, pressure>=30, 在 LATCH | LATCH 处按 E | latch 不变 | 爪抬起、落回、闷响 |
| recovering=true, pressure>=30 | VENT 处长按 E | venting=true | 阀轮再次转动 |

### III.6 三种失败,均可仅凭机械区分

实现中对应 `failReason` 的三个值,按优先级判定:

| `failReason` | 触发条件 | 机械表现 |
| ------------ | -------- | -------- |
| `no-brake` | 未设 BRAKE 就按 LATCH | 指针回升明显快(40/s),0.75s 气路即绷紧,门闩当即拒绝 |
| `latch-bit` | 已刹但从未放气到 30 以下 | 指针**从未离开**红弧;爪抬起一掌高后落回,闷响 |
| `repressurized` | 曾进入低压窗口但抵达时已回压 | 指针**离开后又爬回**红区边界;管路绷紧;爪落下 |

三者互不相同:第一种是"快",第二种是"从未离开红区",第三种是"离开后又回来"。

`repressurized` 的两条真实触发路径(已验证可达,不是死值):

1. 已刹但在车厢里逗留超过 `30/8 = 3.75s` 才按 LATCH;
2. 未刹时放气(窗口成立),走到 LATCH 前才补设 BRAKE —— 此时压力已回到 44.0。

实现上由 `windowAchieved` 区分 `latch-bit` 与 `repressurized`:该字段在 `update()`
中当压力低于阈值时置位,`reset()` 清除,并经 getter 和 `airLockSnapshot()` 暴露,
写点与读点都存在。

失败绝不重置 Section I 或 II。玩家停在原 x,压力继续自行回升,走回 `VENT` 再放一次
即可。`brakeSet` 除玩家主动切换外保持不变。

### III.12 数值决定:恢复速率、窗口时长、步行余量、门闩阈值

四个速率的适用状态:

| 状态 | 速率 | 值 |
| ---- | ---- | -- |
| 放气,未刹 | bleed | 30/s |
| 放气,已刹 | bleedBraked | 21/s |
| 回升,未刹 | recharge | 30/s |
| 回升,已刹 | rechargeBraked | 9/s |

本关围绕**已刹**路径设计,所以支配窗口的恢复速率是 `9/s`。

门闩阈值取红区边界:`latchThreshold = 30`。

已刹、放空到 0 后的低压窗口:

```
t_window = 30 / 9 = 3.333s
```

VENT 2110 → LATCH 2330:

```
d = 220px
t_walk = 220 / 200 = 1.10s
t_margin = 3.333 - 1.10 = 2.233s
```

**未刹路径的对照验算(这是本关的教学机关)**:

```
t_window_unbraked = 30 / 40 = 0.75s  <  t_walk 1.10s
```

未刹时窗口比步行时间短 0.35s,**纯走路必然失败**,所以 BRAKE 是必需而非可选。
玩家永不需要 `speedRun`:已刹路径留有充足余量。

**冻结后的修正(以单元测试为准,已写入 `src/tutorial/airLock.js`)**:

初版取 `RECOVER_UNBRAKED = 26/s`。单元测试证明该值使本关失去教学:满放到 0 后
走 1.10s,未刹只回升 `26 * 1.10 = 28.6`,**仍低于阈值 30**,门闩照样打开,BRAKE
变成装饰。改为 `40/s` 后:

| 状态 | 回升率 | 到 LATCH 时压力 | 对阈值 30 | 结果 |
| ---- | ------ | --------------- | --------- | ---- |
| 已刹 | 8/s | 8.8 | 低 21.2 | 门闩保持打开 |
| 未刹 | 40/s | 44.0 | 高 14.0 | 指针爬过红区边界,爪落回 |

- 未刹失败余量:**14.0 压力单位 / 0.35s**,不是 0.10s 的擦边方案。
- 已刹仍须放气到 **21.2 以下**(约放掉 78.8 单位),所以放气深度依然是有效变量。
- 回满时间:已刹 `100/8 = 12.5s`,未刹 `100/40 = 2.5s`。未刹足够快以被眼睛读到
  "气路在自己回压",又不会瞬间跳满而看起来像 bug。

放气率统一为 `VENT_RATE = 70/s`(不再区分刹车状态),满放 `100/70 = 1.43s`。
刹车只改变**回升**速率,这样"BRAKE 买时间"这一条因果是唯一且干净的。

**为什么修正 MDA 的"~3000ms 恢复"**:原文没有给出压力阈值,也没有给出刹车状态。
未刹回升到 30 只要 `30/30 = 1.0s`,不是 3s;已刹回升到满压要 `100/9 = 11.1s`。
只有"已刹 + 阈值 30"这一组合得到 `30/9 = 3.33s`,所以那个数字指的是**回升到门闩
阈值**的时间,不是回满的时间。取阈值 30 的理由是它同时满足两件事:已刹窗口 3.33s
宽裕地容纳 1.10s 步行,而未刹窗口 1.00s 短于步行时间。

### III.14 独立 QA 路线

1. 从 `x 1610` 开始。预期:压力 100,指针在红区,靠近 1690 时出现 `[E] SET BRAKE`。
2. 走到 `BRAKE` 点按 E。预期:手柄锁住,提示消失。
3. 走到 `VENT`,出现 `[HOLD E] RELEASE AIR`。长按 E。预期:压力以 21/s 下落,
   指针左移,气路变暗并松垂。
4. 在压力 0 时松键。预期:压力以 9/s 回升,一道高光沿 VENT→LATCH 行进。
5. 以普通步行速度走到 `LATCH`。预期:抵达时压力仍远低于 30,出现 `[E] TEST LATCH`。
6. 点按 E。预期:爪抬起并咬住,本关完成。
7. 重开并跳过 `BRAKE`。走到 `VENT` 放空到 0,松键,走向 `LATCH`。
   预期:抵达前压力已达 30,爪抬起后落回并闷响。
8. 设 `BRAKE`,只放气到 50,松键,走到 `LATCH`。预期:指针仍在红区内,爪抬起一掌
   高后落下。
9. 设 `BRAKE`,放空到 0,走到半路停下等待。预期:指针爬过红区边界,管路绷紧,
   随后 `LATCH` 拒绝。
10. 任一次失败后,不离开 Section III 走回 `VENT` 重放。预期:Section I 与 II 未被重置。

### V.3 取代金色高亮的带内信号

**为什么这是后果而不是标签**:转子转动的原因是气流本身 —— 压力落在工作带内时气流
才足以平稳建立力矩。它不是一个"现在对了"的指示器,而是机构在压力合适时的**功能
表现**。没有发光,没有变绿,没有进度条与进度环。玩家必须看和听,而不是读一个提示。

### VI.2 三道闸门谓词 —— 本关的核心修复

废弃 `interactable.def.command === gate.command` 的字符串比较。闸门改为读取
**前三关已经教过的统一机械与压力状态**:

| 闸门 | x | 谓词 | 物理理由 |
| ---- | - | ---- | -------- |

**判定时机(关键决定)**:谓词只在**回声接触闸门触发区的那一瞬**求值。穿行纵深 64px,

直接冲突。瞬间判定让玩家只需**摆出正确的机械状态**,不需要维持时序。

穿过三门后回声走到阀门 4660,转身,双手旋开阀轮并扣住阀兰,持续发力保持开启。此时
上层出口气锁解除、防护栏降下。

终点**。两人各持一端,合起来才算完整地离开这节车厢。

### VI.5 失误、恢复,以及为何没有失败态

玩家摆错状态时,回声只是静止等待,不催促、不消失。玩家看见闸门前那个安静倚着障碍的
身形,就知道此处仍隔着一道墙 —— **全凭机构与姿态自明,没有一个字**。

玩家可自由折返上层:看指针、检查刹车挡位、扳动车钩杆,重新推导对应关系。由于所有

## 总师修正记录(Section IV)

4. **BRAKE 必须在 IV 中作为真实控件存在。** 外部方案把 BRAKE 从 IV 移除,让刹车
   状态从 III 隐式继承。驳回,两个理由:(a) **软锁** —— 任何未刹状态下进入 IV 的
   玩家窗口只有 1.00s,却没有任何控件可以补救;(b) 它把 IV 的玩家能动性削减到只剩
   "放气 + 走路",违反"前一关建立的操作语言必须在下一关继续使用"。现改为进场
   `brakeSet = false`,BRAKE 作为实体控件重新出现在 2470。

   进场即触发提示,读不出"走过去操作"的因果。
6. **压力表 y 从 300 改回 420。** 与 III 同一高度是"相同的压力表读法"这条硬要求
   的一部分;两关表盘不同高会让玩家以为是两个仪器。

   气路恒为 `BRAKE -> VENT -> LATCH`,否则玩家看不到制动与放气之间的物理连接。

## 总师修正记录(Section V / VI)

8. **V.4 的欠调恢复写反了。** 外部方案称"重新设置刹车并短暂开启放风阀让压力上升
   至 35 以上"。放气使压力**下降**,不是上升。欠调(<35)的正确恢复是**松开阀门**
   让压力以 9/s 回升进带,已在正文改正。这类方向性错误必须在施工前拦下,否则会被
   实现成一个玩家永远压不进带内的关卡。
9. **V 的电机不给交互提示。** 转子行为本身就是唯一需要读的东西;加一条 `[E]` 提示
   会把"读机器"退化成"按提示",直接废掉本关的设计意图。
10. **VI 的 PIPE 闸阈值沿用 III 的 30,不引入新数字。** 共同语法要求四关用同一套
    读数;若这里换一个阈值,玩家学到的"低于红区边界即松垂"会失效。
11. **VI 新增唯一一条提示字符串 `[E] SET COUPLER`。** 车钩在本关才成为独立动词,
    沿用 `[E] TEST LATCH` 会让玩家误以为在操作门闩。格式与既有四条一致。
12. **VI 的闸门谓词采用瞬间判定,不采用持续判定。** 穿行仅 0.32s,若要求谓词全程
    为真,玩家须在 0.32s 内维持状态 —— 那是手速题,与"回声可无限等待、张力来自
    理解"的锁定方向冲突。
