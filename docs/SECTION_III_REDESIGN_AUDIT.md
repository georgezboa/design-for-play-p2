## 一、当前实现的真实状态机(已核实)

打卡 → RUN → 指针按 `slotMs` 扫过 3 个槽 → 每槽 `enterSlot` → commit 或 jam → 局部重打。

`enterSlot` 的判定顺序([TimetablePuzzle.js:1373](../src/tutorial/TimetablePuzzle.js#L1373)):
`status === 'done'` 跳过 → `causalBlocker` 不满足则 jam → 不需到场则直接 commit →
到场判定失败则 jam → 无 hold 则 commit → 有 hold 则建立 `drum.hold` 并逐帧判定。

`commitSlot` 设 `machine.brakeSet/ventSet/doorSet` 为绝对真值,`applyDrumAction` 只
**设置**状态不翻转,所以重跑不会撤销已有进度。这一条实现是对的,值得保留。

两份报告的共同前提是"因果规则靠文字交付,应该改成机械表达"。核实后真相更糟:

## 五、三个候选方向

### 方向一(低成本):把面板变成机器,规则不变

复用全部状态机,只重做视觉层级与物理反馈。黑面板改为嵌入车厢内衬的珐琅凹槽 +
黄铜压边;六个同高按钮按**挂载面分离**(BRAKE 落地铸铁支架、VENT 上墙黄铜轮、
DOOR 车厢边缘门闩);新增一条贯穿 y=220 的黄铜主气管,压力以移动亮带表现;
压力表从地面升到视线高度。失败通过闸瓦是否夹紧、气压表针位、门闩是否落下区分。

真实决策仍然是 0。这是清晰度升级,不是设计升级。工作量 2–3 天。

### 方向二(中等):气压是共享资源,顺序不再唯一

保留滚筒与打卡语言,但把 `causalBlocker` 的布尔链换成一个连续的**管路压力值**。
BRAKE 关闭排气阀(压力被困住),VENT 泄压,DOOR 只在压力低于阈值时才能脱闩。
关键改动:**压力会随时间缓慢回升**。于是槽的间距第一次真正重要——泄压后必须在
压力回升到阈值之前让门槽触发。玩家的两个真实决策是:VENT 与 DOOR 之间放几个槽,
以及是否用第三张卡再补一次 VENT 换取更宽的门槽窗口。

失败可从环境读出:门闩抖动但不落下(压力仍高)、气压表针回爬(等太久)、
阀轮只转了一半(按住不足)。工作量 6–8 天。

### 方向三(大胆):抛弃滚筒,改成气锁编程

保留打孔机与时刻表语言,取消指针扫描。玩家把卡插进控制台,机器按顺序执行,
但气锁的物理状态(内外门、压力、排水阀)决定哪些序列合法,且**存在多个合法解**,
其中一个更短。玩家通过观察失败时的物理后果推导规则。

真实决策最多,但它把第三段变成一个独立的逻辑谜题,与前两段的"卡片=命令"关系
断裂,且 10–14 天的工作量超出一个可回退试点的范围。

## 六、最终选择:方向二,并吸收方向一的全部视觉规范

**理由。**

方向一解决了用户的抱怨 1–4(视觉),但对抱怨 5(没有真实决策)无能为力。用户明确
说过"不能通过增加解释文字、箭头、高亮或更大的面板掩盖设计问题"——只做方向一,
等于用更好的美术掩盖一个 0 决策的谜题。

方向三解决了抱怨 5,但代价是丢掉滚筒和"卡片带时间"这条刚建立的语言,并且它
不再是试点——它是重写一段。回退保险 `stage.drum` 在方向三下形同虚设,因为删掉
它之后剩下的排序谜题与新设计毫无关系。

方向二是唯一同时满足两侧的:它让 `slotMs` 第一次有意义(压力回升给了槽间距一个
物理后果),因此产生**两个真实且可理解的判断**——间距与是否补一张 VENT;它继承
方向一的全部视觉重组;而删掉 `stage.drum` 仍然干净回退到共享排序路径。

**它为什么在玩法上优于现状。** 现状的 `causalBlocker` 是布尔链,顺序唯一,间距
无后果。改成带回升的压力值之后,"什么时候"第一次有了答案不唯一的空间,而这正是
本轮最初想要、但 6 槽方案在算术上无法兑现的东西——那次失败的原因记录在
`GAME_DESIGN_MASTER.md` 一bis:槽宽固定、卡数固定、因果唯一,计划空间只有一个点。
压力回升同时松开了这三个约束里的两个。

**它为什么在视觉上优于现状。** 现状是三四个互相竞争的黑色圆角矩形加一个小到看不见
的主人公。新规范把控件按**挂载面**分离(地面/墙面/车厢边缘),用一条可以用眼睛追踪
的气管代替一排等距标签,并把主人公的剪影值提亮到与黄昏外景中间调一致,使他重新
成为画面里最亮的活动物体。

**保留的一项低成本副机制:**VENT 的按住 0.4s。阀门在第五段本来就是按住式交互,
零新增手感成本。不叠加任何其他方向。
