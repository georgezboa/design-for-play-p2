# Phase 1 机制深度与呈现打磨计划

制定日期:2026-07-29
配套文档:[PHASE1_PLAN.md](PHASE1_PLAN.md)(Phase 1 = M1 垂直切片的总体缺口与工作流)
本文档只处理其中两件事:**序章六段机制不够好玩**、**动画与呈现偏弱**。
实施者:GPT-5.6(Codex),按 `AGENTS.md` 的规则只做 `READY` 任务。

## 一、机制为什么不好玩(代码审计结论)

通关整个序章需要 **17 次 `E`**,横跨 4,800px。其中**只有 1 次是真正的决策**
(第三段 `AIR LOCK` 的三命令排序)。其余全部是"唯一选项 / 箭头指着 /
金色高亮 / 代码只允许一个目标响应"。

根因不是关卡设计,是**引导和校验在重复做同一件事,一共做了三遍**:

1. **输入层预校验**:`TimetablePuzzle.js:631-644`(`guideSequence`)和
   `:668-698`(`operateRailControl`)在错误输入进入队列**之前**就拒绝它。
   玩家打不出错误答案。
2. **视觉层报答案**:下一个正确器件被染成金色 `0xf2d49a` 并放大 1.08
   (`:1580-1585`、`:1586-1593`),错误的保持灰色。不需要读机器,读颜色就行。
3. **文本层报答案**:错误提示直接说出正确命令("The wheel is still free.
   Clamp the brake shoe against it first.")。

最直接的证据:`FAIL_LINES` 写了 6 条失败台词,**其中 4 条(索引 0、1、4、5)
在当前代码里永远不可能显示**。第一、二、五、六段结构上无法失败。

其他量化问题:

| 问题 | 现状 | 位置 |
| ---- | ---- | ---- |
| 转向架闸窗过宽 | 3500ms 窗口,只需走 250px(跑动 0.8s),约 2.2s 空余,且**无倒计时 UI** | `level.js:77` |
| 回声同步过宽 | 2 个节点各 2600ms,每次只需移动 200px,可提前站好等灯亮 | `level.js:111-112` |
| 回声失败无代价 | 无限次免费重试同一节点,进度永不丢失 | `TimetablePuzzle.js:1363-1378` |
| 失败无成本 | 仅第三、四段可失败,均在 ~1s 内完全重置,无资源、无位置惩罚 | `:1223-1245` |
| 第五段名不副实 | 标称 `physical-causality`,但金色高亮让"读机器"变成不必要 | `:1592` |
| 死代码 | 260ms resonance hold 属于已废弃的 Below/Above Resonance 设计,不可达 | `GameScene.js:2122-2124` |

## 二、机制修复(按性价比排序)

原则:**不重新设计任何一段关卡,不动美术和叙事框架**。只拆掉冗余引导、
给失败真实成本、把时间窗收紧到有张力。这些改动几乎不增加资产需求。

- **P1 引导分级(最高性价比)。** 给每段加 `guidanceLevel` 字段:
  第一、二段保留全部三层引导(教学);第三段起**撤掉视觉层金色高亮**;
  第五、六段**同时撤掉文本层报答案**,错误提示只描述机器现象
  ("气路仍有压力"),不说该按哪个。预校验只在第一、二段保留。
  单这一条就能把真实决策数从 1 个提到 4 个,零新资产。
- **P2 让四条死掉的失败台词可达。** 第二段去掉 `guideSequence` 硬拦截,
  改成允许打错、执行时暴露后果;第五段错误按键进入队列而不是原地拒绝;
  第六段错过窗口后 PAST 需要多走一圈才回到接点(见 P4)。
- **P3 转向架闸窗:加倒计时,收窄到 2200ms。** 现在 3500ms 无 UI,玩家
  不知道自己在被计时。改动两件:窗口降到 2200ms(仍留 ~1s 余量),
  并在气压表上加一条**真实的机械倒计时**——压力条可见地泄放,读的是机器
  不是数字。这是全序章唯一有张力的机制,值得让它被看见。
- **P4 回声同步:窗口 2600 → 1800ms,失败有成本。** 错过后 PAST 不再原地
  重试,而是**多绕一圈 820ms 才回到接点**,并且已锁定的节点保持锁定。
  失败代价是时间和节奏,不是进度,符合"伙伴不背叛玩家"的定位。
  同时把节点数从 2 提到 3,第三个节点要求玩家**在上层移动中按下**,
  让"和过去的自己合作"进入输入层而不只是动画层。
- **P5 第五段改成"读机器"。** 撤掉金色高亮后补上机器侧的可读状态:
  轮组仍在转 = 还没夹闸;储气罐是满的 = 还没排气;轴电机没转 = 还没通电。
  这些视觉状态**已经存在**(`:1000-1094`),只是被高亮抢了工作。
  同时给三个控制器加"当前是否可操作"的物理反馈(手柄阻滞感 + 闷响),
  让错误按键有触感回馈而不是弹一个报答案的 toast。

## 三、呈现修复(动画与手感)

审计结论:美术方向和环境动效其实做得不错(17 处持续环境动画、
挤压拉伸、完成运镜),弱的是**屏幕级手感、音频、和角色动画帧数**。

- **V1 音频空洞是最大的感官缺口。** 全项目 17 个合成音效、**零音乐、
  零环境循环**。一列会晃、会飘灰的火车是完全静音的。改两件:
  (a) 加一条循环低频轰鸣/嗡鸣底噪(两个失谐振荡器过增益即可,
  `sfx.js` 现有的 `tone()` 原语就够);(b) 给 `tone()` 加 ±5–8% 随机失谐——
  现在 `blocked` 从 10 处调用、`press`/`lever`/`checkpoint` 各 7 处,
  每次响得**完全一样**,听起来像卡带。
- **V2 加屏幕级顿帧(hitstop)。** 全项目 `timeScale` 零使用。撞击、
  受击、闸门落下、同步失败全靠 ≤0.006 强度的抖动,接近感知下限。
  在打卡命中、机械动作落地、同步成功/失败时插入 40–80ms 的
  `time.timeScale` 下沉,这是单位成本最低、体感提升最明显的一条。
- **V3 跳跃和下落没有动画。** `Player.js:171-179` 整个滞空过程只有两张
  静态图,无起跳预备、无落地缓冲。补起跳前 1 帧下蹲、落地后 2 帧恢复。
  另外 `player-idle` 是 4fps 且帧间几乎一样,看起来是张静止图片,
  提到 6fps 并加呼吸幅度;`player-walk` 第 2、3 帧完全重复,改掉。
- **V4 车轮和仪表在运动中是静止的。** 轮辐、飞轮、轴电机只在成功事件时
  一次性转 360°/720°(`TimetablePuzzle.js:1070-1078`)。停站时车轮不动是对的,
  但发车运镜里车轮也不转。把旋转绑到列车状态,这直接服务
  `CLAUDE.md` 里"物理因果可读"的准则。
- **V5 晕影和灯光是冻结的。** 晕影是一张 96x60 静态贴图拉满屏、alpha 永不变
  (`GameScene.js:240-245`)。受击、故障、完成运镜时补上 alpha/色调补间。
- **V6 缓动词汇单调。** ~70 个显式缓动里 23 个是 `Sine.easeInOut`,
  另有约 30 个补间根本没指定缓动(默认线性),包括大部分 HUD 淡入淡出。
  只有 12 个带过冲。机械动作应该用 `Back`/`Bounce` 收尾,气动应该
  快启慢停,不该和淡入淡出用同一条曲线。
- **V7 HUD 没有运动语言。** 血条是瞬切、`[E]` 提示是瞬现瞬隐、
  对话选项零转场且无选中高亮。打字机固定 18ms/字符,标点不停顿、
  无逐字音。补:血条追赶条 + 受击闪白、提示淡入 + 轻微浮动、
  打字机标点停顿 + 逐字轻响。
- **V8 修掉过场的脆弱耦合。** `GameScene.playPrologueDeparture` 和
  `HudScene.showPrologueTransition` 靠**两个文件里各自硬编码的延迟**对齐
  (3500/7000ms vs 2400/3350/5500/6100ms)。改一处另一处会静默失步。
  抽成一份共享时间表常量。

## 四、给 GPT-5.6 的任务序列

拆成三个独立可验收的 `READY` 任务,**按此顺序**,每次只放一个进
`docs/NEXT_TASK.md`。这样做的原因:呈现层改动风险最低且不依赖任何未决
产品决策,先做能立刻让课堂试玩变好看;机制改动会影响难度曲线,需要
在呈现层稳定后再试玩校准。

- **任务 1 — 手感与呈现打磨(V1、V2、V3、V5、V6 局部)。** 不改任何
  puzzle 逻辑、不改关卡数据。范围刻意压在"看得见听得见"的层面。
- **任务 2 — 引导分级与失败可达(P1、P2、P5)。** 只改引导与校验,
  不改关卡布局、不改时间常量。这一步会让序章第一次真的可以打错。
- **任务 3 — 时间窗与回声重构(P3、P4、V4、V8)。** 依赖任务 2 的
  试玩反馈来定最终数值,所以放最后。

第一个任务已经写进 [NEXT_TASK.md](NEXT_TASK.md) 并标记 `READY`。
第一章 `THE SAFETY TEST` 的核心交互决策仍未做,记录在
[PRODUCT_STATE.md](PRODUCT_STATE.md) 的 Current product gap;它阻塞的是
**新内容**,不阻塞上面三个任务。

## 五、明确不做

- 不重新设计六段的任何一段,不改车厢布局、材质语言、叙事框架。
- 不加后处理管线(bloom/色散/颗粒)——`pixelArt: true` 的低像素方向下
  收益可疑,且会拖慢课堂试玩机器。晕影和灯光用现有的贴图+补间解决。
- 不改渲染器配置、不升 Phaser、不动资产管线。
- 不加音乐曲目(只加环境底噪循环),不加音量菜单/混音台。
- 不做第一章内容,不动继承的战斗原型。
