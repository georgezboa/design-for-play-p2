# 序章 Phase II–VI：外部研究与现状审计

日期：2026-08-01
范围：只做研究和审计；不修改玩法代码，不把本文当成最终重构方案。

## 结论先行

当前问题不是“提示不够”或“美术不够好”，而是 **Phase II–VI 没有稳定的可推理链条**。玩家通常不能先看见一个物理状态、提出假设、操作后观察远端后果；相反，他们在多个房间里重复执行“走到装置旁 → 按 E / 长按 E → 等门开”。

更严重的是，现有文档与实际代码已经分叉：设计文档声称 Phase IV 的隐藏 3500ms 窗口应被删除、III–VI 应接入统一气压语法，但当前代码仍保留 `manualWindowMs: 3500`，只有 III 和 V 真正在用气压模型，VI 仍是固定的 BRAKE → VENT → COUPLE 三道闸门。因此现在不是一套失败的统一设计，而是 **三代方案同时存在**。

我的核心判断：

1. **“统一气压”不是正确终点。** 它能统一术语，却会让 III、IV、V 继续像同一道题的换皮版。连贯性应来自稳定的交互语言和可见因果，不是每个房间都用同一数值资源。
2. **III 与 IV 当前高度重叠。** 两者都在问“先做一个动作，再在窗口关闭前赶到远端装置”。IV 只是把气压窗口换成了隐藏计时器，反而更差。
3. **V 与 III 也高度重叠。** 都是 BRAKE 改变气压变化速度、VENT 改变读数，再赶到另一个装置完成；V 的“工作带”只是把阈值从一个点改成一个区间。
4. **VI 的回声概念值得保留，但当前回声不是机制。** 它无限等待，三个障碍各自只接受唯一对应按钮，文字还直接解释答案；玩家没有与过去的自己形成时间关系，只是在替一个 NPC 依次开三道门。
5. **铁路物理被当成标签而非规则。** 真正的自动空气制动中，制动管降压会触发制动、升压会释放制动。当前“先设置 BRAKE 以减慢制动管回压”的表达混合了制动管、储气缸、闸瓦与车体重量等不同系统，玩家即使懂火车也无法靠现实常识推导答案。

因此，现状不适合继续局部打磨。应先确定每一段独有的“核心问题”，再做一次 II–VI 的结构重排。

## 外部研究：真正值得借鉴的不是表面机制

### 1. Split Fiction：稳定的是合作关系，不是具体题型

EA 对游戏的描述强调每关出现新能力与新机制，并在平台、潜行、解谜等类型间变化；但合作行动和时机协调始终稳定。这说明其统一层位于“玩家之间如何互相需要”，不是“每关都重复同一个资源”。

Josef Fares 进一步解释，团队大约每十五分钟引入新机制并抛下旧机制；昂贵的精彩段落也不因成本而反复使用，因为复用会消耗第一次体验的力量。这个原则直接反驳了当前“既然气压系统做出来了，就让 III–VI 都围绕气压”的倾向。

GDC 对 Split Fiction 最终关的介绍还强调：独特概念应被留到适合的位置，揭示要有策略，而且 **简化设计可以给惊奇留出空间**。这意味着 VI 若承担“过去与现在真正合作”的高潮，就不该同时塞进三套装置说明、三段提示文字和三次同构按钮操作。

### 2. It Takes Two：玩家应当“玩到故事”，不是在故事布景里解任意题

Hazelight 的方法不是为了避免重复而随意换玩法，而是先问故事把人物带到了哪里，再设计只有在那个叙事情境中才成立的机制。对本项目来说，车厢、回忆、列车员、过去的自己不能只做皮肤；每一段的操作必须表达“这列车和记忆正在发生什么”。

### 3. Portal 2：持续反馈优于弹跳信息，玩家控制优于隐藏计时

Valve 把一次次弹跳、难以预测的能量球换成持续存在的激光，让玩家随时看见因果；也把部分 timing puzzle 改成开关，让玩家掌握节奏。Phase IV 当前的 3500ms 隐藏窗口正好违反这两点：时间不可见，失败发生在玩家不理解的变量上。

### 4. Mario：介绍、发展、转折、收束，而不是连续介绍新 UI

Super Mario 3D World 常用四段结构：introduce → develop → twist → conclusion。关键是“一条想法的四次变化”，不是四个房间各自发明一套操作词汇。当前 II–VI 既没有围绕单个概念形成完整四拍，也没有在换概念时干净收束前一段。

### 5. Inside / The Witness：空间先提出问题，文字只处理歧义

Inside 用物体摆放、对比、运动和安全环境先抓住玩家注意力，再在压力情境中复用已学动作；The Witness 强调第一层必须极清楚：哪里是谜题、基本操作是什么、怎样算作解答。当前项目的问题恰恰是装置都像按钮，但看不出哪个状态在驱动哪个远端结果；于是文字不得不承担本应由空间和机械动画承担的解释。

## 本轮审计标准

每一段按七个问题检查：

1. 玩家在第一次失败前能否看见规则？
2. 玩家是否需要形成一个假设，而非照亮点/文字执行？
3. 操作是否同时在源头和远端产生可见反馈？
4. 失败是否局部、可恢复、且能说明原因？
5. 空间布局是否参与教学，而非只是增加脚程？
6. 机械关系是否符合世界内部逻辑，至少不会与铁路常识正面冲突？
7. 本段是否发展前一段，并增加一个新的关系，而非重复前一段？

## 逐段审计

### Phase II / CONTACT — 结论：保留教学位置，重做因果表达

**当前结构**：按固定顺序打 BRAKE、POWER，再 RUN。代码不仅拒绝错误顺序，场景目标还明确显示 FIRST: BRAKE / THEN: POWER。

**问题**：

- 真实决策为零；答案在操作前已被系统给出。
- “刹车压低悬挂，使电接点接触”不是一眼可懂的静态铁路关系。若车没有明显的减速、载荷前移或车体下沉动画，BRAKE 与 CONTACT 之间只是程序员写出的关系。
- 玩家关注的是金色标签和文字，不是悬挂与接点。
- 它教会的是“系统会告诉我下一个按钮”，这会污染后面所有需要观察的关卡。

**可保留**：两步教学长度、列车接点美术、RUN 作为“提交并观看机械执行”的早期仪式。

**必须改变的方向**：先让玩家在一个无惩罚空间里看到 BRAKE 使车体/载荷/接点发生明确位移，再让 POWER 成为自然结论。文字最多说明按键，不应说明顺序。

### Phase III / AIR LOCK — 结论：美术和局部状态机可留，谜题核心需重审

**当前结构**：BRAKE 改变回压速度；长按 VENT 把压力降到阈值以下；玩家走 220px 到 LATCH，在压力恢复前开门。

**优点**：

- 已从抽象 timetable 面板转向真实房间内的机械；压力表、管线、门闩形成了潜在的因果链。
- 失败不重置整个房间，三种失败状态在代码中可区分。
- 连续表针比二态开关更适合表达过程。

**问题**：

- 本质仍只有一条解：BRAKE → 把 VENT 放到接近底 → 走到门闩。玩家能犯错，但没有真正选择。
- BRAKE 只改变一个不可直接看见的“回压速率”。如果没有储气缸隔离、阀路切换等明确机械动画，玩家无法从世界推导“为什么刹车会让气压回来得更慢”。
- 这一段已经是一道“制造窗口后跑到远端”的题，导致 IV 无法再用同一种节奏。
- 目标文本在失败后直接说 wheels were never set / line had recharged，仍在替机械解释原因。
- 现实铁路中，制动管降压通常用于施加制动，升压用于释放制动；当前命名让 BRAKE 和 VENT 看起来像两个独立按钮，但其实指向同一制动系统的不同层级，容易产生错误心智模型。

**可保留**：气压表、可变形管线、门闩、局部失败恢复、源头—远端反馈的框架。

**必须改变的方向**：III 应决定自己到底是在教“空气制动的因果”还是“低压时间窗”。不能两者都用半套抽象表达。如果保留时间窗，IV 就必须彻底换题型。

### Phase IV / WEIGHT TRANSFER — 结论：当前玩法应整段推翻

**当前结构**：提交单个 BRAKE 后开启 3500ms 窗口，玩家跑约 350px 去释放 trolley latch；闸瓦颜色和烟雾表达剩余时间。

**问题**：

- 与 III 完全同构：先改变状态，再在窗口关闭前跑到右侧装置。
- “重量转移”没有被做成空间问题。没有可观察的移动质量、重心、斜坡、摆动、反作用或平衡；只有倒计时和脚程。
- 热色与烟雾可以表达“刹车正在过热”，却不能自然表达“远端 trolley latch 还剩多少可操作时间”。视觉反馈的含义与任务变量不一致。
- 设计文档已要求删除 `manualWindowMs`，但实际代码仍在使用，证明当前关卡连设计真相都不唯一。
- 隐藏时间窗让玩家第一次失败前无从预测，失败测试的是是否知道内部数值，不是是否理解重量转移。

**可保留**：trolley、闸瓦发热/烟雾资产可作为别处的状态反馈。

**必须删除**：当前 BRAKE → sprint → RELEASE 的完整逻辑。IV 应成为真正利用长车厢、上下层或移动载荷的空间关，而不是第三关的计时重演。

### Phase V / READ THE BOGIE — 结论：保留车底观察题定位，删除“魔法工作带”

**当前结构**：BRAKE 使泄压和回压变慢；长按 VENT；在压力 30–62 的工作带内按 POWER。

**问题**：

- 与 III 仍是同一压力题：BRAKE 改变速率、VENT 移动表针、到阈值时操作远端装置。
- `objectiveText()` 会明确告诉玩家高于区间就放气、低于区间就回充、进入区间就按 POWER；`pressureHintCommand()` 还会推导下一个控件。名义上是读机器，实际仍是读答案。
- “牵引电机只能在制动管处于中间压力区间时通电”缺少现实依据，也没有足够强的世界内解释。它像为了利用现成表针而造出的规则。
- 车底层本应让玩家观察连杆、轮组、阀体如何共同运动，但当前核心信息仍集中在表和标签上，空间只是把反馈放到了另一层。

**可保留**：车底剖面、轮组、轴电机、连续仪表、诊断关的身份。

**必须改变的方向**：V 应当考“读取机械关系/定位故障”，而不是再考气压窗口。玩家应通过运动不同步、连杆脱开、轮组负载等可见异常找到问题。

### Phase VI / PAST HOLDS THE VALVE — 结论：保留叙事核心，重做全部三闸门逻辑

**当前结构**：过去的自己在下层前进，遇到 wheel / pipe / coupler 三个障碍无限等待；玩家按对应 BRAKE / VENT / COUPLE 后继续；最后回声替玩家按住阀门。

**优点**：

- “过去的自己成为现在的地面”是序章最有叙事潜力的想法。
- 上下层空间和伙伴路径可以让这一段与前面明显不同。

**问题**：

- 三个障碍各自只接受一个固定命令，且顺序完全由位置决定；这不是谜题，是带动画的钥匙序列。
- 回声无限等待，所以玩家没有需要协调的时间、承诺或代价；它不会因为玩家过去的行为而改变，只按当前脚本前进。
- blockedHint / clearedHint 直接解释每个障碍及答案，进一步消除推理。
- “泄压后刚性管道变软并被踩平”“停住轮组就从轮辐间穿过”等画面既危险又不符合可信的列车检修逻辑，容易从神秘变成荒谬。
- 这不是前面机制的综合，因为它没有读取 III 的压力状态、IV 的空间/重量关系或 V 的诊断结果，只比较命令名是否等于当前 gate.command。

**可保留**：过去/现在双层构图、回声角色、最后由过去替现在维持一个状态的叙事结果。

**必须改变的方向**：回声必须由玩家过去真正做过的行为生成，或者至少携带此前操作的时序/路径，而不是现场按脚本等待。VI 的新变量只能有一个：时间关系。其余内容应复用已经清楚教过的两种机械关系。

## 横向问题

### 1. 每段都在更换名词，却没有建立可迁移的知识

CONTACT、AIR LOCK、WEIGHT TRANSFER、BOGIE、PAST 分别像五个小样。玩家从上一段带到下一段的主要知识只是“E 可以操作发光的东西”，不是一个可以继续推理的系统。

### 2. 同一按钮在不同段落里改变含义，但世界没有解释变化

BRAKE 有时是压低车体、有时减慢回压、有时开启计时窗、有时扩大压力工作带、有时让回声穿过轮组。Split Fiction 的机制变化有叙事和场景支持；这里的变化主要来自代码分支，玩家只能记关卡规则。

### 3. 空间是走廊，不是信息

大部分装置沿同一水平线排开。距离主要制造脚程和计时，不承担“先看见后果”“从一个角度发现联系”“上下层互相改变”等教学功能。Phase VI 有上下层潜力，但目前下层只是 NPC 路径。

### 4. 文字同时承担目标、提示、失败原因和答案

目标栏、交互提示、toast、装置标签重复解释同一件事。文字越多，画面越乱；而删掉文字后，机械又不足以独立传达规则。正确顺序不是简单删字，而是先让空间和动画承担因果，再只留下按键词与必要歧义说明。

### 5. 现实逻辑没有统一抽象层

可以为了游戏性简化铁路系统，但必须明确每关模拟的层级：制动管、储气缸、闸缸、闸瓦、悬挂、车钩、牵引电机不能互相充当“一个通用能量系统”。现在不同层级被混用，所以规则既不真实，也不形成稳定的虚构物理。

## 保留 / 重构 / 删除清单

| 部分 | 保留 | 重构 | 删除 |
|---|---|---|---|
| II | 两步教程、接点资产、RUN 仪式 | 让 BRAKE→接点位移可见 | FIRST/THEN 报答案与错误预拒绝 |
| III | 表针、管线、门闩、局部失败 | 明确空气系统层级；只保留一个核心问题 | 隐形速率修正若无机械表达 |
| IV | trolley 与热/烟反馈资产 | 真正的移动质量与空间问题 | 整套 3500ms 冲刺逻辑 |
| V | 车底剖面、轮组、诊断身份 | 改为观察机械异常并定位故障 | 中间气压带 + POWER 的任意组合 |
| VI | 回声、上下层、过去帮助现在的结局 | 回声由真实过去行为驱动 | 三道固定 gate.command 与报答案文字 |

## 对下一轮重构的硬约束

这不是具体方案，而是下一轮任何方案都必须通过的验收门：

1. II–VI 每段写出一句不同的“玩家问题”，不能都包含“在窗口关闭前赶到”。
2. 每段最多新增一个不可见变量；最好所有关键变量都可被机械连续表达。
3. 新规则第一次出现时必须在安全、短距离、单一焦点的空间中展示。
4. 每段至少有一次“玩家操作 A，远端 B 立刻响应”的无遮挡镜头。
5. 失败不能只靠文字解释；玩家应从机械姿态看出失败原因。
6. 同一个动词跨段改变含义时，必须有明确的物理中介，不得只换代码分支。
7. VI 必须读取玩家过去真实产生的数据或路径；否则不叫过去与现在合作。
8. 任何铁路机制先确定抽象层和虚构规则，再命名装置；不能先摆已有资产再编理由。
9. 先做纸面状态图和 30 秒灰盒验证，再动完整美术。
10. 不再继续实现“III–VI 全部统一气压”这条旧路线。

## 风险与证据边界

本轮尝试启动当前本地版本进行 II–VI 连续画面复核，但当前工具会话的网络沙盒禁止监听 `127.0.0.1:5180`（`listen EPERM`），浏览器因此返回连接拒绝；这不是本轮认定的游戏缺陷。因此本文的运行层判断来自现有用户截图、QA 路由结构和实际源码，而不是本轮完整手动通关。该限制不影响对状态机、提示、关卡数据和重复结构的结论，但下一轮进入具体重构前仍需补一次录屏式完整通关审计。
