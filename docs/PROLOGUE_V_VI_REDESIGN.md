# 序章第五、六段重设计 + 运镜穿帮修复

制定日期:2026-07-29
上游文档:[PHASE1_POLISH_PLAN.md](PHASE1_POLISH_PLAN.md)(任务 1 已由 GPT-5.6 完成)
本文档替换原计划里的任务 3,并把穿帮修复并入。

## 一、先回答:一共六段,真正重复的是三段

序章是六段。但重复的不只是最后两段——**第三、五、六段是同一个谜题**。

从 `level.js` 的关卡数据可以直接看出来:

| 段 | 命令 | 结构 |
| -- | ---- | ---- |
| I | `door` | 单命令自动执行 |
| II | `brake, power` | 两命令,有引导 |
| III | `brake, vent, door` | **三命令排序**,无引导 |
| IV | `brake` + 定时扳闸 | 一命令 + 身体动作 |
| V | `brake, vent, power` | **三命令排序**,换成实体控制器 |
| VI | `brake, power, couple` | **三命令排序**,回声替你按掉一个 |

第五段和第六段的数据字段几乎一模一样:都是 `underfloor: true`、
`showRack: false`、`physicalSequence: true`,都是"按正确顺序操作三个实体控制器"。
第六段唯一的区别是 `echoAssist: 'vent'`——回声帮你按掉三步里的一步。

**所以回声现在是排序谜题的装饰品,不是机制。** 这就是你感觉到的重复。
六段里有三段在问同一个问题:"这三个动作该按什么顺序?"

## 二、Split Fiction 的变化原理,套到这列火车上

Split Fiction 不是靠"换机制"取胜的,它靠的是**同一个动词在不同语境下
含义改变**。玩家学会的动词一直有用,但每一段重新定义这个动词**作用在什么上、
受什么约束**。

这个游戏的动词表已经很好了,不用换:`BRAKE`(闸瓦夹紧车轮)、
`VENT`(制动管排气)、`POWER`(轴电机通电)、`DOOR`、`COUPLE`(车钩)。
每个动词都有真实的机械指代物,而且这些美术**已经画好了**——
转向架、轮组、闸瓦、弹簧、储气罐、制动管、牵引电机、车钩全都在
`tutorialTrainRoomsArt.js:144` 那个 `if (stage.underfloor)` 块里。

不该变的是动词,该变的是**语法**。重设计后的六段语法阶梯:

| 段 | 语法 | 玩家学到的新认知 |
| -- | ---- | ---------------- |
| I | 单动词,自动执行 | 我的指令会变成真实的机械动作 |
| II | 两动词,顺序有引导 | 顺序有意义 |
| III | 三动词,顺序无引导 | 我得自己推理因果 |
| IV | 动词 + 身体动作,有时限 | 我自己也是一个物理存在 |
| **V** | **两动词连续使用,维持一个量** | **这些动词是模拟量,不是开关** |
| **VI** | **动词作为另一个人行动的前提条件** | **我的操作是别人脚下的地面** |

第五、六段各自引入一条**全新的语法轴**,而不是第三次问"顺序是什么"。
关键在于:这两个新语法**都无法靠读提示解决**,所以任务 2 撤掉金色高亮
之后它们依然成立——这一点很重要,现在的第五段撤掉高亮后其实是可以
硬猜出来的,因为它本质还是三选排序。

## 三、第五段重设计:`V / HOLD THE LINE`(压力维持)

**新语法:动词是模拟量,不是开关。**

现在:按 `brake → vent → power` 三个控制器,顺序对就过关。
改成:玩家要**维持**一个压力窗口,而不是排一个顺序。

- 储气罐有真实压力值,`VENT` 手柄按住时持续泄压,松开时缓慢回压。
  这两件事的美术都已经存在(`TimetablePuzzle.js:1000-1094` 的储气罐和
  制动管),现在只是被当成两个状态在用,改成连续量。
- 轴电机只在压力处于**中间带**时才能通电——压力太高闸瓦夹死轮组,
  太低则没有气源驱动。玩家必须一边泄压一边判断什么时候够了。
- `BRAKE` 变成压力的乘数而不是一个前置步骤:闸瓦夹得越紧,泄压越慢,
  中间带越宽越好操作,但夹紧本身需要时间。所以玩家会自己发现
  "先夹紧再泄压更容易",这是**推理出来的最优解,不是被告知的正确顺序**。

为什么这解决重复:玩家用的还是那三个动词、那套实体控制器、那套美术,
但问题从"什么顺序"变成"什么时候、多久"。而且它天然抗提示——
高亮一个控制器也没法告诉你该按住多久,所以任务 2 撤引导后依然成立。

失败形态也变了:不是"顺序错了重置",而是压力冲出中间带、电机闷响一声
停转,玩家立刻重试,无进度损失。仪表针从现在的两态跳变
(`:1003` 跳到 28°、`:1042` 跳到 -64°)改成连续跟随压力——
这本身就是一个巨大的呈现升级,而且是**读机器就能玩**的机制,
正好补上原计划 P5 想要的效果。

## 四、第六段重设计:`VI / PAST HOLDS THE VALVE`(互为地面)

**新语法:我的操作是另一个人行动的前提条件。**

现在:回声帮玩家按掉 `vent` 那一步,玩家在两个节点上按对时机。
回声是个便利设施,不按也就是慢一点。

改成:**回声的通行能力由玩家的机械操作决定。**

- 过去的自己在下层沿着转向架走向泄压阀。但下层有三处物理障碍,
  每一处只有玩家在**上层**做对应操作才能通过:
  - 转动的轮组挡路 → 玩家 `BRAKE` 夹住它,回声才能从轮辐间穿过。
  - 制动管横在通道上、带压时是刚性的 → 玩家 `VENT` 泄压,管子软下来,
    回声才能压过去。
  - 车钩缩在里面、回声踩不到 → 玩家 `COUPLE` 把它推出来当踏板。
- 反过来,回声到达泄压阀并按住之后,**上层的门才能开**——玩家没法自己
  同时按住阀门和开门,这是单人游戏里真正需要"两个人"的时刻。
- 关键:玩家看不清下层细节(镜头在上层),只能通过回声的**动作和声音**
  判断它卡在哪一步。这让「向下看」这个已有的运镜语法
  (`GameScene.js` 的 DOWN-look)第一次变成**必要的信息获取**,
  而不是一个奖励性的展示镜头。

这就是 Split Fiction 式的变化:动词完全没换,但 `BRAKE` 的含义从
"让机器停下"变成"给伙伴造一座桥"。玩家对整套动词的理解被重新组织了一次。

而且这修好了一个设计漏洞:回声终于**在机制上不可省略**,同时仍然是
"被编排的伙伴"而不是第二个可操控角色——符合 `PRODUCT_STATE.md` 里
"protagonist is the only directly controlled human"这条已确认的规则。

失败形态:回声卡在障碍前**等待**而不是失败重置。玩家想通了就继续,
没有惩罚也没有时限压力。这比现在的 2600ms 同步窗口更好——
原计划想把窗口收紧到 1800ms 来制造张力,但收紧一个"提前站好等灯亮"
的窗口只会变成手速考试。**换成理解型障碍,张力来自"我不知道该做什么",
这是更好的张力。** 所以原计划 P4 的收窄窗口一条作废。

## 五、运镜穿帮:根因和你猜的相反

你的描述是"前面一关的机制都消失了"。审计结果是:**它们没有消失,
那个位置从来就没画过东西。**

三个原因叠在一起:

1. **整个车底舱美术被 `if (stage.underfloor)` 挡住了**
   (`tutorialTrainRoomsArt.js:144`)。转向架、轮组、闸瓦、弹簧、储气罐、
   制动管、牵引电机、车钩全在这个块里,绘制范围 `y = 600..886`。
   而 `level.js` 里**只有第五、六段**设了 `underfloor: true`。
   第一到四段在 y=600 以下什么都没有,车厢外壳只画到 y=600。
2. **运镜落点和这个开关绑在一起**。`GameScene.js:1897`:
   `const machineY = stage.underfloor ? 720 : 548;`
   镜头 bounds 是 900 高、视口 600,所以 pan 到 720 会被夹到 scrollY=300,
   显示世界的 y=300..900 这一带。对非 underfloor 段,这一带的下半
   (y=600..900)**是完全空白的**——没有外壳也没有车底。前面几段的机械
   都在可见带的上方,下面是没上过色的空洞。
3. **完成运镜把晕影推到 alpha 0.94**(`GameScene.js:1041-1046`),
   晕影是 `scrollFactor(0)`、depth 70,压在所有世界物体之上
   (世界最高 depth 是 61),边缘几乎不透明。于是你正要往下看的时候,
   两侧的旧车厢被压成近黑。空洞 + 压黑 = 你看到的"机制消失了"。

另外 `GameScene.js:226` 那条前景剪影带是纯色 `0x05070b`、
`scrollFactor(0)`、depth 45,镜头下摇时它**不动**,永久遮住屏幕
第 526–600 行里 depth ≤44 的内容,也在帮倒忙。

被排除的嫌疑(都查过了):"移除常驻离屏补间"那次性能修复是清白的,
`setCompletedMachinery` 只调 `killTweensOf` 然后重新设静态姿态,
没有动可见性;`SERVICE SET` 的暗态**是用 alpha 实现的、不是可见性**,
完成段的 `roomPresent` 保持 true;没有任何 cull 设置;没有遮罩;
没有把房间美术挂到摄像机上。

**修法。** 三件事,由浅到深:

- 把车底舱从 `underfloor` 专属改成**每段都有**的服务层。不需要每段都画
  完整转向架,但 y=600 以下必须有连续的车体结构——这本来就是物理正确的,
  一列火车不会只有两节有底盘。
- 让 `machineY` 对齐每段真实的 `underY`(`TimetablePuzzle.js:359` 是 548),
  而不是用一个和 `underfloor` 绑定的三元表达式,这样运镜永远框住真实几何。
- 完成运镜时晕影峰值 alpha 从 0.94 降下来,并且前景剪影带在运镜期间
  要么淡出、要么临时改成世界空间跟着镜头走。

## 六、给 GPT-5.6 的任务顺序(修订)

原计划的三任务改成四个。任务 1 已完成并验收通过。

- **任务 2 — 运镜穿帮修复(第五节)。** 提到第二位,因为它是纯视觉修复、
  不碰任何谜题逻辑,而且**每一次过关都会看到**,是当前最伤沉浸感的问题。
  另外它必须在机制重设计之前做:第五、六段重设计后玩家会更频繁地
  盯着车底看,底下不能是空的。
- **任务 3 — 引导分级与失败可达。** 沿用原计划的 P1、P2,但删掉 P5
  (第五段读机器)——那条被本文档的第五段重设计吸收了。
- **任务 4 — 第五段压力维持重设计。**
- **任务 5 — 第六段互为地面重设计。** 依赖任务 4 的模拟量压力系统
  (第六段的 `VENT` 软化制动管需要连续压力值)。

原计划 P3(转向架闸窗加倒计时、收窄到 2200ms)保留,并入任务 3。
原计划 P4(回声窗口收窄到 1800ms)**作废**,理由见第四节。

## 七、明确不做

- 不换动词表,不加新机械种类,不改材质语言和叙事框架。
- 不把回声变成第二个可操控角色。
- 不加后处理管线(晕影问题用现有贴图 + 补间解决)。
- 不动第一到四段的谜题结构(只给它们补车底美术)。
- 不做第一章内容,不动继承的战斗原型。
