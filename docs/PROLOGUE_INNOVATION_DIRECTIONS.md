## 零、为什么打磨救不了它

试玩后的结论:任务 1-3 的打磨(手感、失败可达、可见倒计时)全部落地了,
玩家仍然觉得"没什么区别"。因为六段共享同一个核心循环:

> 走到打卡架 → 按 E 选命令 → 按 RUN → 站着看机器表演 → 走向下一段

第五段把"选顺序"换成"维持压力"、第六段把"看戏"换成"给回声开路",
但**玩家身体的节奏没变**:静止地输入,然后旁观。真正的创新必须改变
"输入和执行的关系",而不是换一种输入题型。

## 一、核心洞察:时刻表里没有时间

这个游戏的中心道具叫 **TIMETABLE**。现实里时刻表的本质是
**"什么时间发生什么"**。而现在游戏里它只是一个**有序列表**——
打卡顺序决定执行顺序,执行间隔是写死的 540ms,时间轴不存在。

**方向 A(主推):让时刻表真的成为时刻表。**

### A. 排班制(The Living Timetable)

打卡架变成一个**旋转滚筒**(机械钟 / 八音盒滚筒的美术语言,完全符合
既有的时代机械动效方向)。滚筒上有 8 个时间槽,每槽约 1.5 秒。

- 玩家打卡时做两个决定:**哪个命令 + 放进哪个时间槽**。
- 按 RUN 后滚筒匀速转动,指针扫过槽位,扫到有卡的槽,那个命令**在机器上
  当场执行**——伴随一声很响的机械 tick。
- **关键规则:有些命令需要玩家人在机器旁才能完成。** VENT 触发时要有人
  按着阀门,车钩释放时要有人扶着杆。于是排班有了**脚程成本**:
  你把 VENT 排在第 2 槽、DOOR 排在第 3 槽,而它们隔着半节车厢,
  你就跑不过来。
- 谜题从"什么顺序"变成:**顺序 + 间距 + 我自己的路线**。
  玩家给火车写完计划,然后要**活在自己写的计划里**。

为什么这是对的:

1. **把走路变成了玩法材料。** 现在段与段之间的移动是纯粹的死时间;
   排班制下,规划自己的脚程就是谜题本身。不加任何新动词。
2. **难度是玩家自选的。** 滚筒够长,把命令排得稀疏就轻松,排得紧凑
   就紧张且更快完成。教室里最弱的玩家自动获得宽松模式,
   强的玩家自动给自己上难度——**不需要难度选项,张力是 opt-in 的**。
   这直接解决"课堂最弱玩家"和"要有张力"的矛盾,以前所有提案都做不到。
3. **失败是局部的、可看的。** 指针扫到槽、命令触发、你不在场——
   门半开又锁回去、阀门干嘶一声。滚筒转完,卡带弹出,失败的槽位
   烧焦了。**只重打那几个槽**,不是整段重置。
4. **回声系统被统一了。** "被记录的过去"在排班制下有了精确定义:
   **一卷旧卡带在下层重新播放**。第六段变成"对着一份固定的旧时刻表,
   把自己的新动作排进它的空隙里"——二重奏、对位。echoGates 的美术
   全部复用。
5. **直通车厢 2。** 序章:我给火车排班。车厢 2「监考人」:AI 给我排班,
   我盖章裁决。主题反转有了机制载体。

教学阶梯(六段重排):

| 段 | 现在 | 排班制下 |
| -- | ---- | -------- |
| I | 单命令自动执行 | 不变(教打卡这个动作本身) |
| II | 两命令有引导 | 滚筒首次出现,2 个预留槽,间距宽松,教"卡放进槽" |
| III | 三命令排序 | **试点段(实装已收窄)**:3 张卡进 3 个 2.2s 槽,打孔顺序即执行顺序,因果顺序(先闸后排气后开门)不变。新变量只有一个——VENT 和 DOOR 要玩家**到场**,所以计划一旦跑起来,身体就得跟着跑。"自由排槽"是这一行的旧说法,已撤回,理由见"6 槽为何降为 3 槽" |
| IV | 定时扳闸 | 不变——它本来就是"计划外的身体动作",在排班语境下反而更亮 |
| V | 压力维持 | 保留模拟量,但 VENT 的排班槽要求玩家**到场按住**,和压力带天然咬合 |
| VI | 互为地面 | 旧卡带在下层转,玩家把上层动作排进空隙 |

成本的诚实评估:滚筒 UI + 调度执行器是主要开销(中高)。但它是**替换**
现有队列执行器而不是并存——现在的 `puzzle.queue` + 540ms delayedCall 链
本来就是一个退化的调度器,泛化成槽位时间是改造而非重写。

### A 的收尾彩蛋(零机制成本,纯回报)

每段成功的卡带钉在 `SERVICE SET` 房间的墙上(持久房间规则已有)。
最终发车时,列车长把**你写过的所有卡带**装进主滚筒——发车过场就是
你整个序章写下的时刻表连播。**火车按你写的时刻表离站。**
把"教火车说话"这个主题变成看得见的最后一幕。

## 二、其他方向(可叠加,不互斥)

### B. 一个键,四种手(动词手感分化)

E 键不变,但每类器件的**手部动作**不同:打卡是**点按**,阀门是**按住**
(已有),气泵是**连打蓄压**,车钩杆是**按住+在提示瞬间松手**,
调车是**按住 E + 方向键拖着走**。玩家的手指第一次感觉到
"这是五种不同的机器"。成本低,单独上也有效,和 A 叠加更好。

### C. 火车开始接话(共同作者弧线)

序章的机制叙事弧:**教学 → 对话 → 信任**。
- 前三段:玩家单方面下指令。
- 第四段后:滚筒弹出时**火车自己预打了一两个槽**(它在学你)。
  玩家补完剩下的。
- 第五段:火车预打的某个槽**不适合当前工况**(不是恶意,是它没看到
  压力表)。玩家可以覆盖重打——第一次"机器会出错,我来裁决",
  给车厢 2 的监考人主题埋下伏笔。
- 第六段:二重奏(见 A)。

成本低(预打卡只是初始状态),但叙事回报极高:伙伴关系从设定变成机制。

### D. 序章在移动中结束(滚动终章)

发车不该是最后一帧,应该是**最后一段的舞台**。第六段(或发车过场)
开始时车已经在缓慢移动:窗外开始滚动,轮组在转,你在一列**活着的**
火车上完成最后的排班。BRAKE/POWER 的状态直接反映在窗外滚动速度上——
玩家第一次"感到"自己的命令在驱动这列车。运镜语言全部已有。

### E. 窗外的世界是氛围压力(不设失败)

序章中段起,窗外的 AI 搜索光束每隔一段时间扫过站台,一次比一次近。
**纯氛围,永不判定失败**——但它回答了"为什么要出发"并给全章一个
渐强的底噪。和 D 衔接:光束即将扫到本站时,火车恰好动了。

## 三、推荐组合与试点

**脊柱 = A(排班制),弧线 = C(共同作者),终章 = D + E,调味 = B。**

但不要一次全上。**试点:只把第三段改成排班制**(实装为 3 槽 × 2.2s 滚筒、3 张卡;
此处原写 6 槽,已按下文修正)。
理由:第三段是现在唯一有真决策的段落,底子最好;改造范围一段,
失败可回退;试玩只需要回答一个问题——
**"卡片一旦带上时间、玩家必须到场配合,比站着看机器演完好玩吗?"**
(原问法是"给火车排班……比排序好玩吗",但排班能力本轮已撤回,试点答不了那个问题。)
答案是肯定的,再把宽滚筒和自选紧张度扩到 II/V/VI;否定,损失一段的改造量。

## 四、这份提案否决了我自己之前的立场

之前我以"课堂最弱玩家"为由否决了几乎所有结构性提案,只做打磨。
试玩证明那是错的:**动词单一的问题打磨解决不了。**
排班制之所以能过同一道审查,是因为它把难度做成了玩家自选
(稀疏排班 = 简单),而不是把张力做成了门槛。保守立场错在
把"保护最弱玩家"理解成"降低系统复杂度",正确做法是
"让复杂度的代价由选择它的人支付"。

### 6 槽为何降为 3 槽(2026-07-30,实装后修正)

发散稿的 6 槽方案要求每张卡除了选命令还要选槽号,于是打孔台旁必须多一个"槽位
拨盘"控件。三件事一起否掉了它:

1. **算术不成立。** 1.1s 的槽装不下 RUN→阀门的 1.05s 步行加 0.4s 按住,任何相邻
   两槽都无解。玩家能选的其实只有"稀疏"一种排法,选择是假的。
2. **信息不成立。** 3 张卡、3 个必要动作、唯一合法因果顺序 → 计划空间只有一个点。
   槽号拨盘让玩家为一个没有分支的决定多按六次键。
3. **空间不成立。** 房间从 `startX` 1600 到 2378 硬上限,控件最小间距 96px。
   槽位拨盘 + RESET + RUN + 三台机器已经排满;试过再拆三个独立命令键,放不下。

现在打孔台是**一台机器**:三个珐琅字键,`←/→` 选,`E` 打。槽宽翻到 2.2s,让两段
脚程都在纯步行预算内。**滚筒仍然是滚筒**,时间仍然是真实的时间,只是这一段不假装
玩家在编排它。

### 三个候选组合的比较(每个都是 A + 至多一个副方向)

难度必须一步只加一个变量,所以候选一律是 A 加一个,不是 A 加两个。

| 组合 | 玩家新增的决定 | 首次接触的困惑 / 非文字信号 | 最坏试玩结局 |
| ---- | ---- | ---- | ---- |
| **A + B 在场配合** | 排班,并且要排一条自己的身体走得到的路线 | 按 RUN 后站在滚筒边不动,VENT 空放。信号:阀门干响、压力表指针不动、那张卡烧焦 | 步速与槽长没算准,失败读起来像角色速度随机,不像计划失误 |
| **A + C 火车预打槽** | 在火车已占用的槽之间塞进三张卡 | 往已占用的槽打卡没反应。信号:黄铜销已锁死,新卡被顶回来 | 三张卡两个空档,顺手丢进前三个连续空槽就过,决策为零,**执行阶段玩家仍然在旁观** |
| **A + E 搜索光束** | 把命令排到光束不在该器件上方的窗口 | 以为光束是装饰,随手排班后失败找不到原因。信号:火花、光束转红、指针震一下 | 光束周期与槽长撞出唯一安全解,变成试错而不是洞察 |

DeepSeek 的排序把 A+E 排第一、A+B 第二、A+C 第三,理由是 A+E 最便宜、
最好回退。**我不采纳这个排序**,并且不采纳它的成本判断:

- A+E 之所以"便宜",恰恰因为它**不改变执行阶段玩家的身体行为**——
  玩家照样站着看。而本次试玩要回答的问题就是"能不能不再旁观"。
  一个不触碰该问题的试点,即使零成本,也拿不到有用的信号。
  它自己给 A+C 判的死刑("cheap build that produces no useful signal"),
  逐字适用于 A+E。
- A+E 还额外制造一个新的失败原因(光束),而这个原因既不来自
  玩家的计划,也不来自因果链,只来自外部节拍。第三段是第一次
  离开平铺队列,不该同时教两套时间。
- A+C 的否决理由我同意,但更准确的说法是位置错了而不是无聊:
  火车预打槽是**弧线**,它需要玩家先信任滚筒才有戏。第三段还在
  建立信任,提前上会被读成 bug。C 保留给第四段之后。

因此试点选 **A + B(受限的一条)**。它是三者中唯一让玩家在执行阶段
必须用身体的组合;它的最坏结局(数值没算准)是**算术问题,可以在
交付前算掉**,而 A+E 与 A+C 的最坏结局是设计问题,只能靠再做一轮试玩发现。
那道算术已经算完并复核,见下。

### 对发散稿两处数值的修正

1. **槽时长 1.5s → 1.1s,器件重排。** 原布局三个器件在
   1870 / 2017 / 2164(间距 147px)。1.5s 槽 = 300px 的步行预算,
   而全程只有 294px,所以任何排法都走得到,"追着自己的计划跑"不成立。
   **落地布局(实现后复核过的最终值)**:槽位拨盘 1668、RUN 1770、
   BRAKE 1880、VENT 2040、DOOR 2260。1.1s 槽 = 220px。
   稀疏排法(0/2/4 槽)走路可过:到阀门余量 0.34s,到车门余量 0.38s
   ——后者已经把 0.32s 的抬手宽限和 0.4s 的按住时间都付掉了。
   紧凑排法(VENT 2 槽、DOOR 3 槽)那一段步行需 1.6s、跑步需 1.17s,
   都超过 1.1s,**必须往后挪一槽**。张力因此是玩家自己买的。

   与发散稿初稿的三处偏移,都是算术逼出来的,不是审美:
   拨盘要与 RUN 拉开 102px(拾取半径 62px 是最近者胜,再近两个控件会
   互相顶替),因此拨盘落在 1668 而不是 1710;VENT 从 2080 收到 2040、
   DOOR 从 2320 收到 2260,是因为初稿没有为"抬手宽限"留时间,
   按初稿数值走路玩家到车门只剩 0.08s,等于用不是计划失误的理由罚人。
